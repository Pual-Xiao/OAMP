## 一个例子看懂 oamp

下面是一个**真实对话**——用户说了一句话，oamp 从这句话出发，走完了从碎片到知识结构的完整流程。每个概念都在过程中自然解释。

### 起点：一句话

> "不知道蓝色感觉就很吸引我，我喜欢蓝色的海，蓝色的天空，赛里木湖，纯净无暇的蓝色。"

一块碎片。oamp 不会让你建一个"颜色→蓝色"文件夹——那叫归档，不叫思考。

oamp 的工作从这里开始。

### 第一步：深探——找设计问题，不是分类

oamp 的第一步不是整理。是**追问**。三个角度：

**你要正面例子**：赛里木湖——自然水体中的蓝。光穿透水，被吸收、散射、折射。每一层蓝编码了深度和矿物信息。

**你要反面**：oamp 问"有没有你不喜欢的蓝？"——"建筑的玻璃幕墙虽然也很蓝但我一点不喜欢。"玻璃上的蓝是镀膜反射天空——蓝不在玻璃里面，在表面。玻璃拒绝了参与，蓝是天空的复印件。

**你要同类比较**：oamp 继续——"除了蓝，有没有其他东西给你同样的感觉？"——"黑。自然界的黑包含了很多信息不只是黑，而人造的黑是用 RGB 调出来的，数字化的黑我不喜欢。"

自然界的黑有阴影有纹理——黑不是一种颜色，是光被物体遮挡后的**残余**。RGB 黑 `#000000` 是关灯，零信息。

**你要跨界验证**：oamp 再追——"除了视觉，有没有类似体验？"——"声音。听歌手现场演唱和数字版完全不是一个东西。"

现场的声音穿过歌手的身体、气息、肌肉，声音携带了**那具身体在那一刻的全部状态**。数字版剥离了这一切——你的耳机和我的耳机听到同一串 0 和 1。

### 第二步：浮现——找到连你自己都没说出来的东西

五次追问之后，碎片够了。oamp 把五个碎片的设计问题并排放在一起：

| 碎片 | 设计问题 | 关键差异 |
|------|---------|---------|
| 赛里木湖的蓝 | 光穿透水体——蓝的每个层次因深度、矿物而不同 | 蓝**携带了光的旅行日志** |
| 玻璃幕墙的蓝 | 镀膜弹开天空——蓝跟玻璃零因果关系 | 蓝**遗失了因果履历** |
| 自然的黑 | 阴影有形状——黑是"有东西挡住了光"的证据 | 黑**包含了遮挡事件的全部信息** |
| RGB 黑 `#000000` | 像素被命令不发光——没有光、没有物体、没有空间 | 黑**是一句指令，没有过去** |
| 现场演唱 | 声音穿过身体和空气——每个细节都是肉身状态的结果 | 声音**可以反推歌手那一刻的状态** |
| 数字录音 | 文件被解码——扬声器是任意可替换的 | 声音**不携带产生它的过程** |

oamp 不是要你确认"蓝色的东西"和"不是蓝色的东西"。oamp 在做一件完全不同的事：**找出跨越视觉、听觉、触觉的底层共性**。

然后 oamp 把发现反馈给你：

> "你关心的不是颜色，不是声音，不是介质本身。你在乎的是——**一个东西身上能不能读到它自己的历史。**"
>
> 赛里木湖的蓝不是颜色，是光在水中的传记。你能从蓝的层次反推水深、矿物含量——蓝色携带了**因果履历**。
>
> 玻璃幕墙的蓝没有传记。蓝告诉你天空是什么颜色，跟玻璃本身零因果关系——**因果链被剪断了**。
>
> 你拒绝的不是玻璃，不是数字录音，不是 `#000000`。你拒绝的是——一个完美干净但**被剥离了生产历史的结果**，无论它看起来多完美。

你确认了："对了。"

### 第三步：合成——一句话

从你确认的那一刻起，oamp 把你和它的全部对话压缩成**一句话**：

> 偏好携带自身因果履历的事物——结果即过程化石，产物包含自身来历的全部可读痕迹。拒绝被剥离了生产历史的结果。

这句话就是**核心兴趣（Core Interest）**。之后的所有决定——建什么文件夹、用什么字段、写什么内容——都必须能追溯到这句话。超过一句话 = 没想清楚。

### 第四步：推导维度——三根独立的柱子

有了核心兴趣，oamp 从这句话里提取关键词，反向推导**维度（Dimension）**。

维度是一个**独立的信息轴**。就像数据库的列：每一列追踪一件不同的事，沿着任何一列都能独立浏览完整的故事。

| 关键词 | 推导出的维度 | 解释 |
|--------|------------|------|
| "因果履历""生产历史" | **生成模式** | 事物怎么来的？物理相互作用 / 生物过程 / 信号传输 / 数字指令 |
| "可读痕迹""过程化石" | **因果可读性** | 能从结果反推生产过程吗？全部可读 → 部分可读 → 零可读 |
| "携带自身""被剥离" | **时间嵌入** | 结果绑定了特定时刻/地点还是可以无限复现？ |

三维度检查——四项全过：

| 检查 | 结果 |
|------|------|
| 正交 | 模式（什么发生了）≠ 可读性（能看到多少）≠ 时间（何时）——互不重叠 |
| 独立导航 | 沿"物理过程产生的事物"独立可浏览；沿"过程完全可读的事物"独立可浏览；沿"绑定时刻的独特事件"独立可浏览 |
| 完全覆盖 | "因果履历"→生成模式+因果可读性；"可读痕迹"→因果可读性；"被剥离"→因果可读性=零；"过程化石"→时间嵌入+因果可读性 |
| 不可约简 | 删任一维度：一些查询将永远无法实现 |

**关键区分——实例不是维度**：赛里木湖是"物理过程 × 因果完全可读 × 时间绑定"的交点，不是新维度。实例是多个维度交叉的**产物**。存一个文件，从所有相关维度通过 `[[wikilink]]` 链接到达。

### 第五步：文件夹编号——数字就是叙事

oamp 用编号命名文件夹。编号不是随便排的——**编号本身就是因果叙事**：

```
00-入口/          ← 索引入口，第一个看到
01-生成模式/      ← 因果起点：过程类型决定了一切下游可能性
02-因果可读性/    ← 下游：过程中留下了多少可读痕迹？
03-时间嵌入/      ← 再下游：结果能脱离它的时刻存在吗？
04-实例/          ← 三个维度交织的产物
05-交叉专题/      ← 跨维度主题（如"数字复制时代的本真性"）
06-跨界连接/      ← 超出本领域（如"文物修复中的原始痕迹保留"）
07-产出+资料/     ← 输出和原始材料
```

因果链：生成模式 → 痕迹多少 → 时间绑定。颠倒任何一个，叙事断了。**如果重排不影响思考，那就只是归档——oamp 不做归档。**

### 第六步：模板推导（M6）——每个字段都要有"出身证明"

有了维度，oamp 设计**模板（Template）**——每种笔记用哪些字段。

**M6 是什么？** oamp 有 12 个编号方法（M = Method）。每个方法定义：输入什么 → 输出什么 → 什么条件不满足就不能进入下一步。M6 就是"模板字段推导方法"。取编号是因为步骤之间有依赖——M2 的产物是 M3 的原料，不能跳。

M6 的核心规则：**每个模板字段必须能追溯到核心兴趣的一个关键词。追溯不到的，删。**

实例模板字段：

| 字段 | 追溯到核心兴趣的哪个词 | 解释 |
|------|----------------------|------|
| `generation_mode` | "因果履历""生产历史" | 物理过程 / 信号传输 / 数字指令 |
| `causal_readability` | "可读痕迹""过程化石" | full / partial / none |
| `temporal_embedding` | "携带自身""被剥离" | bound（绑定时刻）/ transferable / independent |
| `medium_necessity` | "携带自身" | irreplaceable（介质不可替换）/ replaceable / irrelevant |
| `trace_evidence` | "可读痕迹" | 具体哪些痕迹可反推生产过程（如：蓝色层次→矿物含量→深度） |

**模板铁律**：同名字段在所有模板里必须一模一样。`causal_readability` 在这个模板叫这个，在别的模板不能变成 `CausalReadability`。为什么？因为 Obsidian 数据库按字段名精确匹配——名字不一样 = 两个实例永远不会出现在同一个查询结果中。这不是命名审美，这是**数据可访问性**。

### 第七步：红链——不是 bug，是种子

**红链（Redlink）是什么？** 在 Obsidian 里，`[[some-page]]` 是一个 wikilink。如果 `some-page.md` 不存在，链接显示为红色。

传统笔记工具把红链当 bug——失效链接，清理掉。oamp 把红链当**意图痕迹**：你写 `[[为什么数字复制会剥离因果履历？]]`，页面还不存在，但你**编码了一个想探索的问题**。红链是给未来自己的研究任务。

oamp 要求每条笔记至少 2-3 个红链，且必须是**问题**，不是名词：

- ✅ `[[为什么 RGB 黑不包含任何物理信息？]]` — 拆掉 `[[]]` 是一个完整问题
- ❌ `[[RGB 黑]]` — 拆掉 `[[]]` 只是个名词，没说你到底想探索什么

### 第八步：扩展循环

房间建好了。然后 oamp 进入**扩展循环**：

```
扫描红链 → 找出所有 [[不存在的页面]]
    ↓
逐个决策：填充 / 描述 / 跳过
    ↓
填充 → 写新笔记 → 新笔记留下新红链 → 回到扫描
    ↓
连续两次扫描零新增有意义红链 → 房间成熟
```

- **填充**：红链直接服务核心兴趣 → 写完整笔记
- **描述**：太常识不值得独立成页 → 一两句话解释，去掉 `[[]]`
- **跳过**：不确定 → 保留红链，下次扫描再判断

成熟 ≠ 完成。新想法进来，循环继续。

---

上面这个例子，从"我对蓝色感兴趣"到完整的维度系统、文件夹结构、模板字段——**是一次真实对话的输出**，不是编出来的。这就是 oamp 做的事。

## 为什么这样做

Obsidian 给了无限自由——也因此没有任何内置结构。你可以按任何方式建文件夹。每种分类都合理，但**提前选一种分类就是提前锁定一种理解方式**。你还没想清楚自己在乎什么，文件夹结构已经替你决定了。

oamp 做的事完全相反：**先不建文件夹。先搞清楚你在乎什么。然后从那句话出发，推导出唯一的、因果自洽的结构。** 结构不是整理文件的方式——结构就是你思考的编码。

## 从什么到什么

| 传统做法 | oamp |
|---------|------|
| 先建文件夹，再想放什么 | 先深探碎片的设计问题，再推导结构 |
| 文件夹按字母 / 数量 / 热度排 | 编号即因果叙事：生成模式→痕迹→时间嵌入。顺序变了，思想就变了 |
| "蓝色的事物放在蓝色文件夹里" | 赛里木湖是生成模式×因果可读性×时间嵌入的产物——放实例文件夹，从三个维度链接过来 |
| 模板从已有房间复制 | M6 推导：每个字段必须追溯到这个房间的核心兴趣关键词，追溯不到就删 |
| 红链是失效链接，定期修复 | 红链是意图痕迹：`[[为什么数字复制会剥离因果履历？]]` 是你给自己的研究任务 |
| 笔记要写对的，不确定就不写 | 探索笔记不为正确而写——为暴露你关心什么而写。写完重读，模式从实际写出内容中浮现 |
| 知识库维护靠手工 | 9 个脚本：`freshness` 感知 → `scaffold` 创建 → `migrate` 迁移 → `validate` 验证 → `wikilinks`/`redlinks` 链接 → `unlink` 清理 |

## 质量关卡——不通过就不能前进

每个阶段有阻断条件。上一步不合格，不能做下一步：

| 阶段 | 什么情况下卡住 | 为什么 |
|------|-------------|--------|
| 碎片收集 | < 3 个碎片，或都说不出"它在解决什么设计问题" | 信息不够，继续聊，别急着建结构 |
| 深探 | 没触及底层设计约束，反例没迫使边界定义 | 还是在表面描述，没到设计问题层面 |
| 核心兴趣 | 一句话写不出来，或关键词无法反向推导维度 | 没想清楚，回去提炼 |
| 维度推导 | 不是 3-5 个，或有维度没通过四项检查 | 维度是最关键的骨架——正交、可独立导航、完全覆盖、不可约简，缺一不可 |
| 模式浮现 | < 5 条笔记就急着总结；用户说"嗯…好像也不完全" | < 5 没资格找模式；犹豫就是没确认 |
| 扩展停止 | 连续两次扫描零新增有意义红链 | 已知问题都覆盖了——暂时成熟，新输入随时恢复 |

这些阻断不是惩罚——是保护。防止你在没想清楚的时候建一堆用不上的文件夹。

## 三条路径

不是所有人都从结构开始。oamp 根据你的状态匹配路径：

**结构优先（S1-S5）**：碎片 ≥ 6 且能描述关系 → 先建结构，后填内容。上面的蓝色对话走的是一条接近结构优先的路——碎片一上来就很多，深度也够。

**探索优先（E1-E4）**：刚产生兴趣，碎片 < 6，自己也不确定关心什么 → 写"发现笔记"：不分类、不设维度、不写模板、不加 frontmatter。只管写。写满 5-10 条后重读全文——模式会从你实际写出的内容中自己浮出来。

**用户材料（U1-U5）**：已经有一堆文档、笔记、文章 → 解构原文（提取骨架、分离判断和事实、标记开放问题），然后按因果逻辑重建为结构化知识。

三条路径汇聚于同一个出口：维度 → 文件夹 → 模板 → wiki → 扩展循环。

## 设计来源

oamp 不来自任何现有知识管理框架。每个设计决策从第一性原理推导：

- **一个文件只能在一个文件夹里** → 但可以从多个路径通过 `[[]]` 到达 → 维度系统：一次归档，处处可及
- **编号如果不编码信息就是浪费** → 必须编码因果关系才有导航语义 → 禁止字母序 / 热度序
- **字段名不一致 = 数据永远查不到** → 不是命名审美，是数据可访问性 → 模板铁律：同名字段绝对一致
- **红链 = 变异种子** → 填充有用的，描述常识的，跳过不确定的 → 扩展引擎
- **人在看到自己写了什么之前，不知道自己想什么** → 探索笔记不为正确而写，为暴露而写

不因为"别人都这样做"而采纳任何设计决策。
